# 화면을 한 번 띄워보는 자리

```bash
npm test          # 한 번 돌린다
npm run test:watch
```

APK 빌드가 이걸 먼저 돌린다(`.github/workflows/build-android-apk.yml`). 여기서 막히면
APK를 만들지 않는다.

## 왜 생겼나

하루에 세 판이 깨진 채로 나갔다.

| 무엇 | 어떻게 드러났나 |
| --- | --- |
| `useEffect`의 의존성 목록이 아래에서 선언한 `const`를 가리켰다 | 앱이 **흰 화면**으로 켜졌다. 오류 화면도 없다 |
| 지운 상태를 `async` 함수 안에서 계속 불렀다 | 스캔이 **0%에서 멈췄다**. 콘솔에도 안 뜬다 |
| 후보를 묶은 번호와 등록되는 번호가 달랐다 | 이미 등록한 기프티콘이 **또 등록됐다** |

셋 다 브라우저로 확인했는데 못 잡았다. 이 창은 로그인하고 가족이 있어야 열리는데,
확인은 매번 **로그인 화면까지만** 닿았기 때문이다. 결국 APK를 깔아본 사람이 찾았고,
그때마다 배포 한 판이 날아갔다.

## 무엇을 가짜로 두나

`GalleryScanSheet`는 사진첩(네이티브)·모델(서버)·캔버스에 기대는데 셋 다 여기서는 못 돈다.
**그 셋만** 가짜로 두고 창 자신의 코드는 진짜로 돌린다 — 터진 곳이 전부 창 자신이었다.
가짜를 창 안쪽까지 들이면 정작 볼 것이 안 남는다.

- `utils/gallery` — 사진첩을 읽는 부분만. 폴더 이름 정리 같은 건 진짜를 쓴다
- `utils/imageAnalyze` — 캔버스와 zxing이 도는 자리 (`GalleryScanSheet` 테스트에서만)
- `api` — 서버
- `FamilyContext` — 로그인한 가족

## 무엇을 잡고 무엇을 못 잡나

**잡는다** — 렌더 도중에 죽는 것, 훑기 흐름이 중간에 서는 것, 번호가 어긋나는 것.

**못 잡는다** — 눈으로 봐야 아는 것. 카드가 부드럽게 들어오는지, 스크롤이 따라
내려가는지, 안내멘트가 스무스하게 넘어가는지. jsdom에는 그릴 것이 없다.
그 부분은 여전히 APK를 깔아봐야 안다.

## 새 테스트를 더할 때

**그 테스트가 실제로 그 버그를 잡는지 먼저 확인한다.** 버그를 일부러 다시 넣고
돌려봐서 빨개지는 걸 본 다음에 되돌린다. 통과만 하고 아무것도 못 잡는 테스트는
없는 것보다 나쁘다 — 지켜지고 있다고 믿게 만들기 때문이다.

여기 있는 것들은 전부 그렇게 확인했다.
