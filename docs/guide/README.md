# 모아콘 사용 안내 (새 브로셔)

`docs/manual/`(먼저 만든 것)은 참고용으로 그대로 두고, 여기서 새로 씁니다.

| 파일 | 쓰임 |
| --- | --- |
| `docs/guide/guide.src.html` | **고치는 파일.** 글·배치·장 목록이 다 여기 있습니다. |
| `docs/guide/shots/` | 화면 사진. 가로 600px, JPEG 품질 82로 줄여 넣습니다. |
| `docs/guide/build.py` | src에 sho­ts/를 박아 넣어 `guide.html`을 만듭니다. |
| `docs/guide/guide.html` | **띄우는 파일.** 손으로 고치지 않습니다 — 돌릴 때마다 덮어써집니다. |

## 왜 둘로 나눠 두었나

브로셔는 웹으로 띄우는데, 거기서는 바깥 주소로 그림을 못 불러옵니다. 그림이 파일 안에
통째로 들어가 있어야 해요. 그런데 9장까지 가면 화면이 마흔 장 가까이 되고, 그만큼의
긴 문자열이 박힌 파일은 열어서 고칠 수가 없습니다. 그래서 **고치는 파일과 띄우는
파일을 나눕니다.**

```
python3 docs/guide/build.py
```

## 고치는 법

장은 `guide.src.html` 아래쪽 `CHAPTERS` 배열에서 나옵니다. 장 하나가 객체 하나예요.

- `state: 'wait'` → 차례에 "캡처 대기"로 뜨고, 아래에 `need`(보내주실 화면)가 붙습니다
- `state: 'done'` → "작성됨"으로 바뀌고 `body`에 넣은 내용이 나옵니다

즉 **차례만 봐도 어디까지 왔는지, 다음에 무엇을 찍어야 하는지** 알 수 있습니다.

## 화면 사진 넣기

0. 화면이 길어 두세 번에 나눠 찍었다면, 겹치는 부분을 찾아 한 장으로 이어붙입니다
   (겹침 높이를 픽셀 차이로 찾아 잇습니다 — `shots/main.jpg`가 그렇게 만든 것입니다)
1. 받은 캡처를 `shots/이름.jpg`로 줄여 넣습니다 (가로 600px).
   **자르지 않습니다** — 폰 화면 통째로 두어야 넉 장을 나란히 놓았을 때 크기가
   똑같아 깔끔합니다. 내용에 맞춰 잘라보니 칸마다 높이가 달라져 지저분했습니다
2. src에서 `<img src="shots/이름.jpg" alt="...">`로 가리킵니다 — 경로는 `shots/`로 시작해야
   build.py가 알아봅니다
3. `python3 docs/guide/build.py`

한 장에 딸려 오는 빈 여백이 많으면(알림처럼 화면 위 한 줄이 전부인 경우) 카드를 잘라낸
비율로 두고 `object-position`으로 보여줄 자리를 잡습니다. 표지의 세 장이 그 예입니다.

## 쓸 때 지키는 것

- 읽는 사람이 20대부터 아버지 세대까지입니다. **본문 18px**, 한 항목은 **제목 한 줄 + 설명 두 줄까지**
- 기능 이름 말고 하는 일로 씁니다 — "찜 기능"(X) → "내가 쓸게요 표시"(O)
- 화면에 적힌 글자는 `<span class="ui">사용완료</span>`처럼 그대로 인용합니다
- **실명을 넣지 않습니다.** 가족은 `우리 가족`, 사람은 `아빠 / 엄마 / 아들 / 딸`
  (목데이터의 받은 사람도 이 넷으로 맞춰뒀습니다 — `client/src/sampleData.js`)
- **브랜드 로고는 쓰지 않습니다.** 상호는 화면 안의 글자로만 나오고, 맨 아래 고지문으로
  제휴가 아님을 밝힙니다

## 자리잡은 모양 (계속 지킬 것)

- **번호는 차례가 있을 때만.** 1장의 로그인 네 걸음처럼 순서대로 해야 하는 것에만 번호를
  붙입니다. 0장의 세 가지처럼 나란한 이야기에는 붙이지 않습니다
- **꼭 짚어야 할 것은 `.warn` 상자로.** 연보라 바탕만 쓰고 왼쪽에 굵은 선은 두지 않습니다.
  상자 안의 `.ui` 인용 칩만 바탕을 흰색으로 뒤집습니다(바탕색이 같아 칩이 안 보이므로)
- **화면 사진은 붙이기 전에 확인합니다.** 브라우저가 서로 다르면 `최근 로그인` 같은 표시가
  다른 자리에 붙어 나옵니다. 나란히 놓을 두 장은 같은 조건에서 찍은 것만 씁니다
- **걸음(`.steps`)은 넓은 화면에서 가로로 눕습니다.** 860px부터 네 칸으로 늘어서서
  흐름이 한눈에 들어오고, 좁은 화면에서는 위아래로 쌓입니다. `subgrid`로 사진 줄과
  글 줄을 나눠 써서 설명 시작점을 맞춥니다. 이 규칙들은 기본값을 덮어써야 하므로
  **반드시 기본 `.step` 규칙 뒤에** 둡니다. subgrid는 사진↔글 간격도 `.steps`의
  세로 gap을 따라가 버리므로, 줄과 줄 사이는 `.step > div`의 `padding-bottom`으로
  따로 벌립니다 — 안 그러면 넉 장이 한 줄로 끊기지 않고 죽 이어져 보입니다
- **가로로 누우면 글은 한 칸에 두세 줄까지.** 칸이 좁아 길게 쓰면 빼곡해 보입니다.
  한 걸음에 **35~45자 한 문단**이 기준이고, 빠진 설명은 아래 `.warn` 상자로 내립니다
- **강조는 화면 사진에 양보합니다.** 화면 사진이 이미 브랜드 보라로 가득해서, 걸음
  번호까지 보라로 두면 강조가 셋(사진·인용 칩·번호)이 겹쳐 산만해집니다. 번호는
  잉크색이고, 보라는 `.ui` 인용 칩에만 남겨둡니다
- **사람이 바뀌는 장에는 `.who` 이름표를 답니다.** 역할마다 색이 다릅니다 —
  만드는 쪽은 청록(`--host`), 초대받은 쪽은 주황(`--guest`), 둘 다면 회색입니다.
  같은 색이면 두 사람이 한 사람으로 읽힙니다. 2장처럼 만드는 사람과 초대받은 사람이
  번갈아 움직이면, 화면만 봐서는 지금 누구 차례인지 알 수 없습니다
- **화면 하나를 짚는 장은 `.call`.** 걸음(`.steps`)과 다른 갈래입니다 — 순서가 아니라
  자리를 가리킵니다. 짚는 자리에 `.pin`(번호)을 얹고, 옆에 같은 번호로 설명을 세웁니다
  - 번호 자리는 **눈대중으로 읽지 말고 사진에서 직접 잽니다.** 바탕과 다른 픽셀의 행·열
    분포로 요소 경계를 뽑고, 카드 안은 가로 구분선으로 윗줄과 버튼줄을 가릅니다.
    확대해서 보면 눈대중은 반드시 어긋나 있습니다
  - 번호 색은 앱 보라(`--accent`)를 씁니다. 화면 사진은 페이지 테마와 무관하게 늘 밝아서,
    흰 테두리(`box-shadow`)를 둘러야 화면 속 보라 버튼과 겹쳐도 번호가 떠 보입니다
  - **번호가 글자를 덮으면 옆으로 비켜둡니다.** 붉은 D-day 칩이나 + 버튼처럼 작은 것은
    한가운데에 놓으면 정작 가리키려던 것이 안 보입니다
  - **화면이 길면 두 장으로 자릅니다.** 아홉 군데를 한 장에 다 얹으면 사진이 너무 깁니다
  - 사진은 넓은 화면에서도 **500px까지만** 키웁니다. 세로로 긴 폰 화면이라 폭을 키우면
    스크롤만 늘어납니다. 좁은 화면에서는 사진 아래로 설명이 쌓입니다
- **캡처에 들어간 개인정보는 가립니다.** 로그인 계정 이메일이 화면에 그대로 찍힙니다.
  줄어든 600px 사진에서 그 줄만 모자이크로 덮습니다(2장의 1·3번 걸음이 그 예)

## 이어서 할 일

차례에 `캡처 대기`로 뜬 장이 남은 일입니다. 그 장의 `need`에 어떤 화면이 필요한지 적혀
있습니다. 사진을 받으면 `shots/`에 넣고 `state: 'done'`으로 바꾼 뒤 `body`를 씁니다.

한 가지 남겨둔 것 — 2장 캡처에 **실제 초대코드 `E6D4E4`가 그대로 찍혀 있습니다.**
승인 없이는 아무도 못 들어오니 당장 위험하지는 않지만, 브로셔를 밖으로 내보낼 거라면
그 전에 시험용 가족을 새로 만들어 다시 찍는 편이 깔끔합니다.
