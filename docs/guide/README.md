# 모아콘 홍보 브로셔

처음에는 사용 안내서로 쓰다가, 너무 세세해져서 **홍보용 브로셔**로 방향을 바꿨습니다.
A부터 Z까지 설명하지 않습니다 — 무엇이 좋은지와, 시작하는 데 꼭 필요한 것만 담습니다.
(먼저 만든 `docs/manual/`은 참고용으로 그대로 둡니다.)

| 파일 | 쓰임 |
| --- | --- |
| `docs/guide/guide.src.html` | **고치는 파일.** 글·배치가 다 여기 있습니다. |
| `docs/guide/shots/` | 화면 사진. 가로 600px, JPEG 품질 82~86. |
| `docs/guide/build.py` | src에 shots/를 박아 넣어 `guide.html`을 만듭니다. |
| `docs/guide/guide.html` | **띄우는 파일.** 손으로 고치지 않습니다 — 돌릴 때마다 덮어써집니다. |

```
python3 docs/guide/build.py
```

## 왜 둘로 나눠 두었나

브로셔는 웹으로 띄우는데, 거기서는 바깥 주소로 그림을 못 불러옵니다. 그림이 파일 안에
통째로 들어가 있어야 해요. 그런데 그만큼의 긴 문자열이 박힌 파일은 열어서 고칠 수가
없습니다. 그래서 **고치는 파일과 띄우는 파일을 나눕니다.**

## 짜임새

읽는 사람이 위에서 아래로 한 번에 훑도록 여섯 덩이입니다.

| 자리 | 무엇 | 쓰는 모양 |
| --- | --- | --- |
| 표지 | 한 문장 + 화면 세 장 | `.cover` · `.fan` |
| why | 기프티콘이 잊히는 세 가지 이유 | `.points` |
| what | 모아콘이 하는 일 여섯 가지 | `.points` |
| screens | 쓰는 모습 세 장 | `.gallery` |
| main | 메인 화면 한눈에 | `.call` · `.pin` |
| start | 시작 세 걸음 | `.steps` |
| safe | 안심할 수 있는 이유 셋 | `.points` |

## 쓸 때 지키는 것

- **매리트를 먼저, 사용법은 최소한만.** 안내서가 아닙니다. "어떻게 누르는지"보다
  "무엇이 좋아지는지"를 앞에 둡니다
- 읽는 사람이 20대부터 아버지 세대까지입니다. **본문 18px**, 한 항목은 **제목 한 줄 +
  설명 두세 줄**
- 기능 이름 말고 하는 일로 씁니다 — "찜 기능"(X) → "내가 쓸게요 표시"(O)
- 화면에 적힌 글자는 `<span class="ui">사용완료</span>`처럼 그대로 인용합니다
- **실명을 넣지 않습니다.** 가족은 `우리 가족`, 사람은 `아빠 / 엄마 / 아들 / 딸`
- **브랜드 로고는 쓰지 않습니다.** 상호는 화면 안의 글자로만 나오고, 맨 아래 고지문으로
  제휴가 아님을 밝힙니다

## 화면 사진 규칙

1. 화면이 길어 나눠 찍었다면 겹치는 부분을 찾아 한 장으로 이어붙입니다
   (겹침 높이를 픽셀 차이로 찾습니다 — `shots/main-a.jpg`가 그렇게 만든 것입니다)
2. 가로 600px로 줄여 `shots/이름.jpg`. **자르지 않습니다** — 폰 화면 통째로 두어야
   여러 장을 나란히 놓았을 때 크기가 같아 깔끔합니다
3. **캡처에 들어간 개인정보는 가립니다.** 로그인 계정 이메일이 로그인 화면과 알림에
   그대로 찍힙니다. 그 줄만 모자이크로 덮습니다(`login` · `family-new` · `family-join` ·
   `lock` · `push`가 그 예)
4. src에서 `<img src="shots/이름.jpg" alt="...">`로 가리킵니다 — 경로가 `shots/`로
   시작해야 build.py가 알아봅니다

## 자리잡은 모양

- **꼭 짚어야 할 것은 `.warn` 상자로.** 연보라 바탕만 쓰고 왼쪽에 굵은 선은 두지 않습니다.
  상자 안의 `.ui` 인용 칩만 바탕을 흰색으로 뒤집습니다(바탕색이 같아 칩이 안 보이므로)
- **걸음(`.steps`)은 넓은 화면에서 가로로 눕습니다.** 860px부터 나란히 늘어서고, 좁은
  화면에서는 위아래로 쌓입니다. `subgrid`로 사진 줄과 글 줄을 나눠 써서 설명 시작점을
  맞춥니다. 이 규칙들은 기본값을 덮어써야 하므로 **반드시 기본 `.step` 규칙 뒤에** 둡니다.
  subgrid는 사진↔글 간격도 `.steps`의 세로 gap을 따라가므로, 줄과 줄 사이는
  `.step > div`의 `padding-bottom`으로 따로 벌립니다
- **`.gallery`도 같은 이유로 subgrid를 씁니다.** 잠금화면이 목록보다 길어서, 그냥 두면
  아래 설명이 제각각 다른 높이에서 시작합니다
- **번호 태그(`.pin`)는 "메인 화면 한눈에" 한 곳에만 씁니다.** 화면 하나를 놓고 자리를
  가리키는 자리라서요. 나머지는 걸음(`.steps`)이나 나란한 갈래(`.points`)로 씁니다
  - 번호 자리는 **눈대중으로 읽지 말고 사진에서 직접 잽니다.** 바탕과 다른 픽셀의 행·열
    분포로 요소 경계를 뽑습니다. 확대해서 보면 눈대중은 반드시 어긋나 있습니다
  - 번호 색은 앱 보라(`--accent`). 화면 사진은 페이지 테마와 무관하게 늘 밝아서,
    흰 테두리(`box-shadow`)를 둘러야 화면 속 보라 버튼과 겹쳐도 번호가 떠 보입니다
  - **번호가 글자를 덮으면 옆으로 비켜둡니다.** 붉은 D-day 칩처럼 작은 것은 한가운데에
    놓으면 정작 가리키려던 것이 안 보입니다
