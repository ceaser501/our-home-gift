# 출시 전 전체 검수 목록

앱을 내보내기 전에 사람이 직접 한 번씩 해보는 것들. 자동 테스트가 못 잡는 것만 모았다 —
기기 권한, 실제 장소, 실제 사진, 서버 배포 같은 것들이다.

평소 개발 중에는 [docs/next.md](next.md)를 보고, **이 문서는 출시 직전에 처음부터 끝까지
한 번 훑는다.**

## 아직 한 번도 확인 못 한 것

여기 있는 것은 "안 될 것 같다"가 아니라 **"확인할 기회가 없었다"**는 뜻이다.

### 위치를 못 잡는 곳

지하철·지하주차장처럼 위치가 안 잡히는 데서 앱을 열어야 확인된다.

- [ ] 지하에서 앱 열기 → **"지금은 위치를 확인할 수 없어요. 지하나 실내에서는 안 잡힐 수 있어요."**
- [ ] 그 띠에 **X가 없어야** 한다 (닫으면 그날 하루 안 뜨는 규칙에 걸린다)
- [ ] 밖에 나와서 앱 다시 열기 → 저절로 사라지고 매장 안내로 바뀐다

### 위치 권한을 처음 묻는 자리

이미 권한을 준 기기에서는 안 보인다. **앱 데이터를 지우거나 새 계정**으로 들어가야 한다.

- [ ] 기프티콘이 있는 상태에서 앱 열기 → **"위치 권한을 켜면 근처에서 쓸 수 있는 기프티콘을 알려드려요. [켜기]"**
- [ ] **누르기 전에는 시스템 권한 창이 안 떠야 한다** (무시해도 권한이 타지 않아야 한다)
- [ ] 켜기 → 시스템 창 → 허용 → 곧바로 매장 안내로 바뀐다
- [ ] 켜기 → 거절 → 그날은 다시 안 묻는다. 다음 날 다시 한 번 묻는다
- [ ] 기프티콘이 하나도 없으면 묻지 않는다

### 관리자 명단

`supabase/admin-users.sql`을 돌린 뒤에 본다. **주인 계정(90tskim)과 그 외 계정 둘 다**
필요해서 혼자서는 절반만 확인된다.

- [ ] 주인으로 들어가면 사이드바에 **관리자 관리**가 있다
- [ ] 다른 관리자로 들어가면 **그 메뉴가 없다**
- [ ] 이메일을 넣으면 명단에 서고, 그 계정으로 로그인하면 들어와진다
- [ ] **가입 안 한 이메일도 넣어진다** (계정 칸이 「아직 없음」)
- [ ] 그 사람이 나중에 가입하면 계정 칸이 「있음」으로 바뀐다
- [ ] 주인 줄에는 빼기 버튼이 **없다**
- [ ] 넣은 사람을 빼면 다음부터 못 들어온다
- [ ] **관리자가 모아콘에서 계정을 지워도** 명단에 남고, 다시 가입하면 그대로 들어온다

### 아이폰

빌드 자체가 아직 없다.

- [ ] 여러 장 등록이 되는지 (아이폰에서는 이것이 유일한 다건 경로다)
- [ ] 사진첩 훑기 버튼이 안 보이는지 (지원하지 않는 것이 맞다)
- [ ] **[설정 열기] 버튼이 보이는지** — 지금은 안드로이드에서만 뜬다. 스위프트 쪽을 만들고
      판정을 풀어야 나온다. 무엇을 고쳐야 하는지는
      [docs/store-release.md](store-release.md)의 5번에 적어뒀다

## 금액권을 나눠 쓴 기록 (2026-08-26)

**`supabase/gifticon-uses.sql`을 먼저 돌려야** 확인된다. 안 돌리면 사용 내역이 통째로 빈다.

5만원권 하나를 두 사람 이상이 나눠 써야 보인다.

- [ ] 엄마가 3,000원, 딸이 20,000원 쓰면 **사용 내역에 두 줄**이 서는지
- [ ] 각 줄의 금액이 **그 사람이 쓴 만큼**인지 (액면 5만원이 아니라)
- [ ] 「누가 썼나요」 합계가 사람별로 갈리는지
- [ ] 필터에서 「엄마」를 고르면 3,000원 한 줄만 남는지
- [ ] 예전에 쓴 것들이 그대로 남아 있는지 (SQL이 한 줄씩 옮긴다)

### 사용취소

- [ ] 5만원권을 다 쓰고 사용취소 → **마지막에 쓴 금액만** 잔액으로 돌아오는지
- [ ] 그때 「◯◯원이 다시 남았어요」가 뜨는지
- [ ] 엄마·딸이 쓴 줄은 **사용 내역에 그대로 남는지**
- [ ] 보통 기프티콘(금액권 아닌 것)은 사용취소하면 예전처럼 그냥 돌아오는지
- [ ] 그 기프티콘의 사용 내역 줄이 없어지는지

### 알림도 같이

- [ ] 금액권을 조금 쓰면 종에 **「◯◯원 썼어요」**가 뜨는지
- [ ] 목데이터(9000111122…)로는 알림이 안 뜨는지. **사용 내역에는 떠야 한다** —
      알림만 걸러내고 기록은 남긴다

## 계정 탈퇴

되돌릴 수 없는 자리라 한 번은 실제로 해봐야 한다. **스토어 심사에서도 보는 항목이다.**

2026-08-17에 실제로 해봤다. 메모를 남긴 계정도, 사진을 여러 번 올렸다 지운 계정도
지워졌고, 같은 메일로 다시 가입하니 새 사람으로 들어왔다. 혼자 남은 가족도 정리됐다.

남은 것은 이름 표시 하나다.

- [x] 메모를 남긴 적 있는 계정으로 탈퇴 → 지워진다
- [x] 사진을 여러 번 올렸다 지웠다 한 계정으로 탈퇴 → 지워진다
- [x] 탈퇴 뒤 같은 메일로 다시 가입 → 새 사람으로 들어온다
- [x] 혼자 있던 가족은 통째로 없어진다
- [ ] 가족이 남아 있으면 내가 쓴 기록이 **`아들(탈퇴한 구성원)`**으로 남는지
      (알림·사용 내역·메모 셋 다. 예전에는 이름을 지우고 '탈퇴한 구성원'만 남겨서
      누구 얘긴지 알 수 없었다)
- [ ] 막히는 날이 오면, 창에 뜬 문구에 **표.칸 이름과 건수**가 적혀 있다
      (`public.user_delete_blockers`. "storage.objects.owner 3건"처럼 나온다.
      짐작하지 말고 그걸 보고 고친다)

## 창이 다른 창으로 갈리는 자리

계정 삭제는 두 번 묻는다. 앱에서 창이 같은 자리에서 통째로 갈리는 곳은 여기뿐이고,
그 자리에서 뒤로가기 장치가 어긋나 두 번째 물음창이 뜨자마자 스스로 닫혔다. 탈퇴 버튼을
누를 기회가 없어서 서버로는 아무것도 나가지 않았다.

**이 종류는 jsdom 테스트로 안 잡힌다.** 테스트의 `.click()`은 진짜 pointerdown을 만들지
않아서, 겹친 창끼리 부딪히는 일이 아예 일어나지 않는다. 실제로 이 버그는 테스트를 다
통과한 채로 나갔다. 진짜 브라우저에서 눌러봐야 한다.

- [ ] 계정 삭제 → 계속 → **"정말 탈퇴할까요?"가 화면에 남아 있는지** (깜빡이고 사라지면 그 버그다)
- [ ] 탈퇴하기를 눌렀을 때 개발자도구 Network에 `delete-account` 줄이 생기는지
- [ ] 뒤로가기로 물음창을 닫으면 그 창만 닫히고 내 메뉴는 남는지
- [ ] 겹쳐 뜬 시트(가족 → 이름 바꾸기)에서 뒤로가기가 한 번에 하나씩 닫는지

## 상품명 재확인 (2026-08-18)

하이쿠가 전부 읽고, **상품명만** 소네트에게 그 사진 한 장을 통째로 보여 다시 물어본다. 틀리는
항목이 상품명 하나로 몰려 있고, 틀린 방식이 조용해서(따먹는처럼 멀쩡해 보인다) 사람이
못 걸러낸다. 기본으로 켜져 있다. 끄려면:

```
supabase secrets set ANALYZE_VERIFY_MODEL=off
supabase functions deploy analyze-gifticon
```

- [ ] 테스트 빌드 카드 진단줄에 `상품명 확인됨`이 뜨는지 (안 뜨면 함수가 안 올라간 것)
- [ ] 투썸 `떠먹는`으로 `상품명 고침(따먹는 … →)`이 뜨는지 — **이게 이번 작업의 목표다**
- [ ] 배스킨라빈스처럼 **맨 위 띠에 인사말이 큼직한 카드**에서 상품명을 제대로 잡는지
- [ ] 짧은 이름(아이스 아메리카노 T)이 확인 뒤에도 **안 바뀌는지** (헛고침이면 더 나쁘다)
- [ ] `상품명 재확인 못 함`이 자주 뜨지 않는지
      (자주 떴다면 소네트가 생각하느라 512토큰을 다 쓰고 잘린 것이었다. 생각을 껐다)
- [ ] 읽는 데 걸리는 시간이 얼마나 늘었는지 — 시간 표시줄로 잰다
      (생각을 끄기 전 확인이 4초대였다. **그보다 확 줄어야 함수가 올라간 것이다**)
- [ ] `ANALYZE_VERIFY_MODEL=off`로 두면 예전처럼 도는지

## 막대를 못 읽은 사진 알리기 (2026-08-19)

카톡이 404x677로 줄여 보낸 배스킨라빈스 카드는 막대 하나가 1.4픽셀이라 **어떤 배율로도
못 읽는다**(1·2·3·4·6배를 정밀 탐색 켜고 끄고 열 번 다 재봤다). 그런데 훑기는 막대를
읽어야 후보를 만들기 때문에, 사용자 눈에는 그 기프티콘이 세상에 없었던 것처럼 보였다.

그래서 못 읽었다는 사실과 어디를 뒤져야 하는지를 알려준다. 다만 못 읽은 것 전부를 세면
서른 장 중 스물몇 장이 밥 사진이라 말이 쓸모없어진다 — **막대로 보이는 것만** 센다
(읽는 것과 있는지 보는 것은 다른 일이다).

- [ ] 자동스캔 끝에 `바코드로 보이는데 못 읽은 사진이 카카오톡 2장 있어요`가 뜨는지
- [ ] 하나도 없으면 **안 뜨는지** (없는데 뜨면 밥 사진을 열어보게 만든다)
- [ ] 그 숫자가 실제 기프티콘 수와 맞는지 — **여기가 이 기능의 합격선이다.**
      2026-08-19에 39장 중 2장을 짚었고 둘 다 배스킨라빈스였다(오탐 0)
- [ ] 테스트 빌드 목록에서 `▮`가 붙은 것만 세어지는지

## 인식이 멈췄을 때 뭐라고 하는지 (2026-08-18)

크레딧이 떨어져 함수가 500을 뱉은 날, 화면은 **"잠시 뒤에 다시 시도해주세요"**라고 했다.
기다려서 낫는 일이 아니었는데도 그렇게 말해서 원인을 찾는 데 반나절이 갔다. 이제
갈라 말한다. `supabase functions deploy analyze-gifticon`을 해야 바뀐다.

- [ ] 크레딧이 없거나 키가 틀리면 → **"이미지 인식이 멈췄어요. 관리자에게 알려주세요."**
- [ ] 저쪽이 붐빌 때(429·5xx) → **"지금은 붐벼요. 잠시 뒤에 다시 시도해주세요."**
- [ ] 우리 코드가 틀렸을 때만 예전 500 문구가 남는지 (남의 탓으로 돌려 묻히면 안 된다)
- [ ] Supabase 함수 로그에 `kind`와 `status`가 찍히는지

## 알아두면 헷갈리지 않는 것

검수하다 "버그인가?" 싶을 때 여기를 먼저 본다. **다 의도한 동작이다.**

- **관리자 로그인은 이제 시간으로 안 끊긴다.** 토큰 자체는 여전히 한 시간짜리지만
