- 점검 시점: 2026-08-05
- 전제: 프론트엔드가 백엔드 없이 Supabase를 직접 호출하는 구조(PWA). 인증은 Supabase Auth, 데이터 접근 제어는 RLS, 서버 로직은 Edge Function.
- 범위: `client/`, `supabase/schema.sql`, `supabase/functions/*`

## 1. 네이버 로그인 오픈 리다이렉트

**문제.** `supabase/functions/naver-auth`가 `state`에 실려온 주소로 아무 검증 없이 리다이렉트한다.

**위험.** 이 함수는 마지막에 Supabase가 발급한 `action_link`로 리다이렉트하는데, 그 링크는 **열기만 하면 세션이 만들어지는 링크**다. 공격자가 `state`를 조작한 네이버 로그인 URL을 피해자에게 보내면, 피해자가 로그인한 뒤 그 링크가 공격자 사이트로 넘어간다. 계정 탈취가 가능하다.

**조치 (완료).** 허용 origin 목록을 만들고, 목록에 없는 주소면 로그인을 중단한다.

- 허용 목록은 `NAVER_ALLOWED_REDIRECTS`(쉼표로 구분)와 기존 `NAVER_LOGIN_FALLBACK_REDIRECT`를 합쳐서 만든다. 둘 다 운영자만 설정할 수 있는 값이다.
- **검증을 `redirectTo`를 쓰기 전에 한다.** 오류 안내조차 그 주소로 돌려보내는 구조라, 검사를 뒤에 두면 오류 경로가 그대로 우회로가 된다.
- 허용 목록이 비어 있으면 로그인을 진행하지 않는다(fail-closed). 설정이 빠졌을 때 열리는 쪽으로 넘어지지 않게 했다.
- 비교는 문자열 앞부분 대조가 아니라 `new URL(...).origin`으로 한다. 주소 형식이 아니면 거부한다.

**검증.** 배포될 파일에서 함수 본문을 그대로 떼어와 돌렸다(사본이 아니라 실제 코드).

| 입력 | 결과 |
|---|---|
| `https://ceaser501.github.io/our-home-gift/?x=1` | 허용 |
| `http://localhost:5173/` | 허용 |
| `https://evil.com/steal` | 거부 |
| `https://ceaser501.github.io.evil.com/` | 거부 |
| `https://evil.ceaser501.github.io/` | 거부 |
| `https://ceaser501.github.io@evil.com/` | 거부 |
| `http://ceaser501.github.io/` (스킴 다운그레이드) | 거부 |
| `//evil.com` (상대 경로) | 거부 |
| `javascript:alert(1)` | 거부 |
| 설정이 하나도 없을 때 — 우리 주소마저 | 거부 (fail-closed) |

**운영자가 해야 할 것.**

```
supabase secrets set NAVER_ALLOWED_REDIRECTS="https://ceaser501.github.io,http://localhost:5173"
supabase functions deploy naver-auth
```

`NAVER_LOGIN_FALLBACK_REDIRECT`를 이미 넣어뒀다면 그 주소는 자동으로 허용되므로, 로컬 개발 주소만 추가하면 된다.

## 2. AI·외부 API 함수에 인증이 없음

**문제.** `analyze-gifticon`, `search-price`, `search-places` 세 함수 모두 호출자를 확인하지 않는다.

Supabase Edge Function의 기본값 `verify_jwt = true`는 **anon key를 유효한 JWT로 받아들인다.** anon key는 클라이언트 번들에 그대로 들어 있어 누구나 꺼낼 수 있으므로, 이 설정은 인증이 아니다.

**위험.** 누구나 아래처럼 부를 수 있고, 그때마다 Anthropic API 크레딧·카카오 쿼터·TMAP 종량 요금(초과분 건당 10원)이 나간다. 스크립트로 반복하면 하룻밤에 큰 금액이 나갈 수 있다.

```
POST https://<프로젝트>.supabase.co/functions/v1/analyze-gifticon
Authorization: Bearer <anon key — 공개된 값>
```

**조치.** (대기)

## 3. 이미지 버킷이 공개 상태

**문제.** `gifticon-images` 버킷이 `public = true`라, URL을 아는 사람은 로그인 없이 이미지를 볼 수 있다.

**위험.** 기프티콘 이미지에는 **바코드(=금전적 가치)**와 이름이 찍혀 있다. 경로가 추측하기 어렵게 생긴 것(`family_id/시각-uuid.jpg`)은 방어가 아니다. 한 번 새어나간 URL은 영구히 유효하고, 가족에서 나간 사람이 예전에 본 URL을 계속 쓸 수 있다.

**조치.** (대기)

## 4. 업로드 파일 크기·형식 제한 없음

**문제.** 화면에서 `file.type.startsWith('image/')`만 확인한다. 이는 파일 선택 단계의 편의 필터라 우회가 쉽다. 스토리지 버킷과 정책에는 크기 제한도 MIME 제한도 없다.

**위험.** 로그인만 하면 자기 가족 폴더에 임의 크기의 임의 파일을 올릴 수 있다. 스토리지 요금이 늘고, 파일 저장소로 악용될 여지가 있다.

**조치.** (대기)

## 5. 개인정보처리방침·이용약관

**문제.** 저장소에 없다. Apple·Google 모두 필수라 없으면 심사에서 리젝된다.

**담아야 할 것.**
- 수집 항목: 이메일, 표시 이름, 기프티콘 이미지, 위치(매장 찾기)
- 보관 기간과 파기 절차 — 계정 삭제 기능이 하는 일을 그대로 기술
- 제3자 처리위탁: Supabase(저장), **Anthropic(이미지 분석)**, 카카오(장소·지도), TMAP(보행 경로), 네이버(로그인·가격 검색)

- 위치정보는 위치정보법상 별도 동의가 필요한지 확인이 필요하다.

## 7. `CRON_SECRET` fail-open

**문제.** `send-expiry-notifications`의 검사가 이렇게 돼 있다.

```js
if (cronSecret && url.searchParams.get('token') !== cronSecret) { ... 401 }
```

`CRON_SECRET`이 설정돼 있지 않으면 조건 전체가 거짓이 되어 **검사를 통째로 건너뛴다.** 시크릿을 실수로 지우거나 이름을 잘못 쓰면 아무나 알림 발송을 트리거할 수 있다. 보안 검사는 설정이 빠졌을 때 **막는 쪽(fail-closed)**으로 넘어져야 한다.

**조치.** (대기)

## 9. 가족 내 권한 — 조치하지 않음 (의도된 설계)

**지적된 내용.** 가족 구성원이면 누구나 다른 사람이 올린 기프티콘을 수정·삭제할 수 있다. 승인 실수로 모르는 사람이 들어오면 전부 지울 수 있다.

**결정: 그대로 둔다.** 사용자 판단이다. 이 앱은 가족이 기프티콘을 **함께 쓰는 것**이 목적이고, "엄마가 받은 걸 아빠가 쓰고 사용 완료로 바꾸는" 흐름이 정상 동작이다. 올린 사람만 수정할 수 있게 하면 그 흐름이 막힌다. 서로 다 보는 사이라는 것이 이 앱의 전제이므로, 권한을 나누는 것은 실질적으로 얻는 것 없이 쓰기만 불편해진다.

모르는 사람이 들어오는 문제는 권한 분리가 아니라 **참여 승인 절차**로 막는다(이미 구현됨).

## 12. 운영자도 복호화할 수 없는 암호화 — 보류

**요청 내용.** 운영자가 DB에서 남의 기프티콘 이미지를 꺼내 볼 수 있는 것이 사용자에게 불안 요소다. 운영자도 못 푸는 방식으로 암호화할 수 있는가.

**결론: 지금 단계에서는 하지 않는다.** 근본적인 충돌이 있다. 클라이언트에서 암호화하면 서버는 이미지를 읽을 수 없고, 그러면 **AI 자동 등록이 원리적으로 불가능해진다.** 이 앱의 핵심 편의 기능을 포기해야 한다.

현실적인 절충은 이렇다.
1. 버킷 비공개 + 서명 URL (3번) — URL 유출로 인한 노출을 없앤다
2. AI에 보내는 사실을 방침에 정직하게 명시 (5번)
3. 계정 삭제 시 이미지까지 실제로 삭제 — **이미 구현됨**

나중에 다시 볼 만한 방향은 "바코드 부분만 클라이언트에서 암호화"다. AI 분석은 원본으로 하고, 저장은 바코드만 가린 채로 하는 식. 다만 설계가 커서 별도 과제로 둔다.
