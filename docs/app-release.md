# 안드로이드 앱 배포 가이드

웹만 해오다가 앱을 처음 뿌리는 사람을 위한 문서다. 명령어를 그대로 복사해 쓸 수 있게
적었고, 왜 그렇게 하는지도 웹에 빗대어 함께 적었다.

실제 설정 파일은 `.github/workflows/build-android-apk.yml`과 `app/capacitor.config.ts`다.

> **스토어에 올릴 거라면 [docs/store-release.md](store-release.md)를 먼저 본다.**
> 이 문서는 지인에게 APK를 직접 나눠주는 방법이고, 스토어 배포에는 규칙이 더 붙는다.

---

## 1. 웹 배포와 뭐가 다른가

웹은 **서버 한 곳만 최신이면 끝**이다. 파일을 올리면 그다음 접속하는 사람은 전부 새 화면을 본다.

앱은 **사람마다 자기 폰에 복사본을 갖는다.** 그래서 웹에는 없던 문제가 생긴다.

| | 웹 (지금까지) | 앱 (APK) |
| --- | --- | --- |
| 배포 | `git push` → Pages가 갱신 | APK 파일을 만들어 **링크로 나눠줌** |
| 사용자가 받는 법 | 주소 접속 | 링크 → 다운로드 → **설치** |
| 최신 반영 | 새로고침하면 끝 | 각자 다시 설치해야 함 |
| 신원 증명 | HTTPS 인증서 (CA가 발급) | **앱 서명 키 (내가 발급)** |
| 버전 관리 | 필요 없음 | `versionCode`가 반드시 올라가야 함 |

### 화면은 앱 안에 담겨 나간다

한동안은 앱이 GitHub Pages 주소를 그대로 띄우게 해뒀다(`server.url`). 웹만 배포하면 앱도
같이 갱신돼서 APK를 다시 뿌릴 일이 거의 없었다. **스토어에 올리기로 하면서 그 방식을 버렸다** —
애플과 구글 모두 심사를 통과한 뒤 화면이 바뀌는 구조를 금지한다. 자세한 사정은
[docs/store-release.md](store-release.md)에 있다.

그래서 지금은 화면을 고치면 **앱도 새로 빌드해서 나눠줘야 한다.** 위 표의 "각자 다시 설치해야
함"이 그대로 적용된다.

개발 중에 매번 새로 까는 건 낭비라, 환경변수를 준 빌드에서만 예전처럼 원격 주소를 띄우게
열어뒀다. **이 빌드는 나눠주면 안 된다.**

```bash
cd app
MOACON_DEV_SERVER=https://ceaser501.github.io/our-home-gift/ npx cap sync android
```

## 2. 새로 알아야 할 개념 4개

### (1) 서명 키 — HTTPS 인증서와 비슷하지만, 내가 발급한다

안드로이드는 **서명된 앱만 설치**된다. 서명은 "이 앱과 다음 업데이트가 같은 사람이 만든 것"을
증명한다.

웹의 HTTPS 인증서와 다른 점이 둘 있다:

- **CA(인증기관)가 필요 없다.** 내가 만든 키를 그대로 쓴다. 승인도 비용도 없다.
  (아이폰은 반대다. 애플이 발급한 인증서가 없으면 앱이 아예 실행되지 않는다. 이게 iOS에
  연 $99가 드는 이유다.)
- **만료돼도 갱신하는 게 아니라, 잃어버리면 끝이다.** 아래 경고를 꼭 읽어야 한다.

> ⚠️ **키를 잃어버리면 되돌릴 방법이 없다.**
> 다른 키로 서명한 APK는 이미 깔린 앱 위에 **덮어쓰기가 안 된다.** 안드로이드가
> "다른 사람이 만든 앱"으로 보기 때문이다. 쓰던 사람 전부가 앱을 지우고 다시 깔아야 한다.
> (기프티콘 자료는 Supabase에 있어서 남지만, 다시 로그인해야 한다.)
>
> `moacon.keystore` 파일과 비밀번호를 **저장소 밖에** 백업해둔다. 비밀번호 관리자나
> 개인 클라우드에 둔다. 저장소에는 절대 커밋하지 않는다.

### (2) versionCode와 versionName — 둘은 역할이 다르다

| | 무엇 | 예 | 누가 본다 |
| --- | --- | --- | --- |
| `versionCode` | **정수.** 폰이 "이게 더 새것인가"를 판단하는 **유일한** 기준 | `47` | 아무도 안 봄 |
| `versionName` | 사람에게 보여줄 이름 | `1.0.0` | 설정 화면에 표시 |

`versionCode`가 이전보다 크지 않으면 폰이 업데이트를 거부한다. 그래서 사람이 적지 않고
**GitHub Actions 실행 번호를 그대로 넣게 해뒀다**(`github.run_number`). 늘 커지기만 하니
실수할 여지가 없다.

`versionName`은 태그에서 가져온다. `app-v1.0.0` 태그를 밀면 `1.0.0`이 된다.

### (3) 패키지명(applicationId) — 한 번 정하면 못 바꾼다

지금 `io.github.ceaser501.moacon`으로 되어 있다(`app/capacitor.config.ts`).

웹의 도메인 같은 것으로, **폰이 앱을 구분하는 이름**이다. 이걸 바꾸면 안드로이드는 완전히
다른 앱으로 본다 — 기존 앱 위에 업데이트가 안 되고, 두 개가 따로 깔린다.

**바꾸려면 사람들에게 나눠주기 전, 지금이 마지막 기회다.**

### (4) 설치 출처 — "알 수 없는 앱"

스토어를 거치지 않은 APK를 설치하는 걸 사이드로딩이라 한다. 안드로이드는 이걸 기본으로
막아두고, 사용자가 직접 허용해야 열어준다. 받는 사람이 겪을 마찰의 대부분이 여기서 나온다
(→ 5장).

## 3. 준비 — 딱 한 번만 하면 된다

### 3-1. 서명 키 만들기

`keytool`은 JDK에 들어 있다. 자바가 없으면 [Temurin](https://adoptium.net)을 설치한다.

```bash
keytool -genkeypair -v \
  -keystore moacon.keystore \
  -alias moacon \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -storetype PKCS12
```

실행하면 이렇게 물어본다:

```
키 저장소 비밀번호 입력:          → 비밀번호를 정해서 입력 (6자 이상). 화면에 안 보인다
새 비밀번호 다시 입력:            → 같은 값
이름과 성을 입력하십시오.         → moacon  (아무거나 좋다)
조직 단위 이름을 입력하십시오.    → 그냥 엔터
조직 이름을 입력하십시오.         → 그냥 엔터
구/군/시 이름을 입력하십시오.     → 그냥 엔터
시/도 이름을 입력하십시오.        → 그냥 엔터
두 자리 국가 코드를 입력하십시오. → KR
...이(가) 맞습니까?               → y
```

여기 적는 이름·조직은 인증서 안에 들어가지만, 스토어를 안 거치면 아무도 보지 않는다.
비워도 된다. **`-validity 10000`은 약 27년**이라 사실상 만료를 걱정할 일이 없다.

`-storetype PKCS12`라 키 비밀번호를 따로 묻지 않는다. **비밀번호는 하나뿐이다.**

### 3-2. GitHub 시크릿에 넣기

키 파일을 워크플로가 쓸 수 있게 넣어준다. 파일은 그대로 넣을 수 없으니 텍스트로 바꾼다:

```bash
base64 < moacon.keystore | tr -d '\n'
```

출력된 긴 문자열을 통째로 복사한다. (`tr -d '\n'`은 줄바꿈을 없애는 것으로, 맥·리눅스
어디서든 같게 나오게 하려는 것이다.)

그다음 저장소에서 **Settings → Secrets and variables → Actions → New repository secret**으로
4개를 등록한다:

| Name | Secret |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | 방금 복사한 긴 문자열 |
| `ANDROID_KEYSTORE_PASSWORD` | 3-1에서 정한 비밀번호 |
| `ANDROID_KEY_ALIAS` | `moacon` |
| `ANDROID_KEY_PASSWORD` | 3-1에서 정한 비밀번호 (PKCS12라 위와 같은 값) |

시크릿은 등록하면 다시 볼 수 없다(덮어쓰기만 된다). 원본 파일과 비밀번호를 따로 보관해야
하는 이유이기도 하다.

## 4. 배포하기 — 매번 하는 일

### 4-1. 태그를 민다

```bash
git tag app-v1.0.0
git push origin app-v1.0.0
```

`app-v`로 시작하는 태그만 이 워크플로를 깨운다. 다른 태그를 써도 앱 빌드는 돌지 않는다.

### 4-2. Actions 탭에서 지켜본다

저장소 **Actions → Build Android APK**. 5~10분쯤 걸린다. 하는 일은:

1. `client`를 빌드해서 앱 안에 넣을 화면을 만든다
2. `npx cap sync android`로 그걸 안드로이드 프로젝트에 복사한다
3. 시크릿에서 키를 꺼내 파일로 풀고
4. `./gradlew assembleRelease`로 서명된 APK를 만든다
5. Release를 만들고 APK를 붙인다

### 4-3. 링크를 나눠준다

`https://github.com/ceaser501/our-home-gift/releases` 에 `moacon-1.0.0.apk`가 올라온다.
파일을 우클릭해 주소를 복사하거나, Release 페이지 주소를 그대로 카톡에 보내면 된다.

> **APK 파일 자체를 카톡이나 메일로 보내지 않는다.**
> 카톡에 올린 파일은 일정 기간이 지나면 만료돼서 나중에 받는 사람이 못 받는다.
> Gmail은 아예 `.apk` 첨부를 차단한다. **반드시 링크로 준다.**

시험 삼아 빌드만 해보고 싶으면 Actions 탭에서 **Run workflow**로 수동 실행한다. 그때는
Release를 만들지 않고 실행 결과 아래에 APK만 첨부한다.

## 5. 받는 사람은 무엇을 겪나 (갤럭시 기준)

여기가 웹과 가장 다른 부분이고, 미리 안내해두지 않으면 "바이러스 아니냐"는 연락이 온다.

### 정상적으로 뜨는 경고들

1. **다운로드할 때** — "이런 유형의 파일은 기기에 위험을 줄 수 있습니다"
   → 그대로 **다운로드** / **확인**
2. **설치를 누르면** — "이 출처의 앱을 설치할 수 없습니다" 하고 설정 화면으로 보낸다
   → **이 출처 허용** 토글을 켠다 (앱별 설정이라, 크롬으로 받았으면 크롬에만 켜면 된다)
3. **설치 직전** — Play Protect가 "알 수 없는 개발자의 앱..." 경고
   → **자세히 → 무시하고 설치**

세 번 다 정상이다. 스토어를 안 거친 앱이면 누구나 겪는다.

### ⚠️ 갤럭시라면 먼저 확인할 것 — "보안 위험 자동 차단"

One UI 6(안드로이드 14)부터 삼성에 **[보안 위험 자동 차단(Auto Blocker)](https://www.samsungsvc.co.kr/solution/1711930)**
이 생겼다. **이게 켜져 있으면 위 3단계를 아무리 해도 설치가 안 된다.** "알 수 없는 앱" 메뉴
자체가 잠겨서, 공식 스토어 앱만 깔린다.

껐다 켜는 법:

> **설정 → 보안 및 개인 정보 보호 → 보안 위험 자동 차단 → 끄기**

기기와 One UI 버전에 따라 기본값이 다르고, 최근 기기일수록 켜져 있는 경우가 많다.
**설치가 안 된다는 연락이 오면 십중팔구 이것이다.** 안내문에 미리 적어두는 편이 낫다.
(설치가 끝난 뒤에는 다시 켜도 앱은 그대로 동작한다.)

### 아이폰인 사람에게는

이 APK를 쓸 수 없다. 지금처럼 `https://ceaser501.github.io/our-home-gift/` 에 접속해서
**공유 → 홈 화면에 추가**로 쓰면 된다. 기능은 갤러리 자동 스캔만 빼고 같다.

## 5-2. 앱에서의 로그인 — 왜 따로 손대야 했나

앱을 처음 띄웠을 때 소셜 로그인을 누르면 **브라우저가 열리고, 로그인은 거기서 끝나고,
앱은 로그아웃 상태 그대로** 남는 문제가 있었다.

`client/src/auth.js`가 구글·카카오·네이버 로그인 화면으로 페이지를 넘기는데, 그 주소는
우리 도메인이 아니다. Capacitor는 앱이 띄우는 화면의 출처 밖으로 나가려 하면
**외부 브라우저로 넘긴다.** 그래서 로그인 전체가 브라우저에서 진행되고, 끝나고 돌아오는
주소도 웹 주소라 앱으로 돌아올 길이 없었다.

화면을 앱 안에 담아도 똑같이 생기는 일이다. **웹뷰와 OAuth의
구조적인 문제**다.

### 웹뷰 안에서 처리하면 안 되나

안 된다. **구글이 앱 내장 웹뷰에서의 로그인을 정책으로 막아뒀다**(`disallowed_useragent`).
카카오톡 인앱 브라우저에서 구글 로그인이 안 되는 것과 같은 이유다.

### 그래서 쓰는 방법 — 크롬 커스텀 탭 + 딥링크

```
앱에서 "구글로 로그인"
  → 크롬 커스텀 탭이 앱 위에 덮이듯 뜬다 (앱을 떠나지 않는다)
  → 구글 로그인
  → 끝나면 io.github.ceaser501.moacon://login 으로 리다이렉트
  → 안드로이드가 이 스킴을 우리 앱에 넘긴다 (AndroidManifest의 intent-filter)
  → client/src/utils/deepLink.js가 토큰을 받아 setSession
  → 커스텀 탭이 닫히고 로그인된 앱이 보인다
```

### 이 주소는 네 곳이 같아야 한다

한 곳이라도 다르면 로그인이 브라우저에서 끝난다. 증상이 똑같아서 어디가 틀렸는지
알기 어려우니, 바꿀 일이 생기면 네 곳을 함께 고친다.

| 어디 | 무엇 |
| --- | --- |
| `client/src/utils/deepLink.js` | `NATIVE_REDIRECT_URL` 상수 |
| `app/android/.../AndroidManifest.xml` | `<data android:scheme="@string/custom_url_scheme" />` |
| Supabase 대시보드 | Authentication → URL Configuration → **Redirect URLs** |
| Supabase 비밀값 | `NAVER_ALLOWED_REDIRECTS` (네이버 로그인을 쓸 때만) |

### 이메일 로그인 링크는 조건이 하나 붙는다

메일함의 링크는 앱이 아니라 브라우저에서 열린다. 브라우저가 로그인을 확인한 뒤 위 딥링크로
넘기면 앱이 받아 열리므로 결과적으로는 동작하는데, **메일을 그 폰에서 열어야 한다.**
노트북에서 열면 그 기기에 앱이 없어서 딥링크가 열리지 않는다.

### 커스텀 스킴의 한계

`io.github.ceaser501.moacon://` 는 다른 앱도 같은 스킴을 등록할 수 있다. 그 앱이 깔려 있으면
로그인 결과를 가로챌 여지가 있다. 이를 막으려면 App Links(도메인 소유 증명)가 필요한데,
`github.io`는 루트에 증명 파일(`/.well-known/assetlinks.json`)을 올릴 수 없어서 지금은 못 쓴다.
가족·지인이 쓰는 규모에서는 감수할 만하지만, 공개 배포로 갈 때는 다시 봐야 한다.

## 6. 업데이트는 어떻게 되나

**앱에는 자동 업데이트가 없다.** 스토어를 안 거치니 새 버전을 밀어줄 통로가 없어서다.

| 무엇을 고쳤나 | 어떻게 반영되나 |
| --- | --- |
| Edge Function, DB 스키마 | 서버 쪽이라 앱과 무관하다. 그대로 반영된다 |
| React 화면, 스타일, 문구 | **새 APK가 필요하다** (화면이 앱 안에 담겨 있다) |
| 네이티브 코드(갤러리 스캔, 권한, 아이콘, 앱 이름) | **새 APK가 필요하다** |

새로 뿌릴 때는 태그를 하나 더 밀고(`app-v1.1.0`) 같은 링크를 다시 안내하면 된다.
같은 키로 서명돼 있으니 **기존 앱 위에 덮어써지고 로그인도 유지된다.**

받는 사람이 옛 버전을 계속 쓰는 걸 막을 방법이 없다는 게 이 방식의 약점이다. 스토어에
올리면 자동 업데이트가 붙어서 이 문제가 사라진다(→ [store-release.md](store-release.md)).

## 6-2. 개발 중에는 매번 설치하지 않아도 된다

위 표는 **남에게 나눠줄 때** 이야기다. 내가 고치면서 확인할 때는 대부분 재설치가 필요 없다.

| 무엇을 고쳤나 | 재설치 | 확인 방법 |
| --- | --- | --- |
| 화면·스타일·문구·JS 로직 | **필요 없음** | 아래 라이브 리로드. 저장하는 순간 폰에 반영된다 |
| 자바 코드(`GalleryPlugin.java` 등) | 필요함 | `./gradlew installDebug` (1~2분) |
| `AndroidManifest.xml`, 권한, 아이콘, 앱 이름 | 필요함 | 위와 같음 |
| `capacitor.config.ts` | 필요함 | `npx cap sync android` 후 위와 같음 |
| Edge Function, DB | 필요 없음 | 서버 쪽이라 앱과 무관하다 |

**대부분의 수정은 첫 줄이다.** 태그 → Actions → 다운로드 → 설치를 반복할 이유가 없다.

### 라이브 리로드 — 화면을 고치면 폰에 바로 뜬다

맥과 폰이 **같은 와이파이**에 있어야 한다.

```bash
# 터미널 1 — 개발 서버를 네트워크에 연다
cd client
npm run dev -- --host
#   Network: http://192.168.0.12:5173/   ← 이 주소를 쓴다
```

```bash
# 터미널 2 — 앱이 그 주소를 보게 만든다 (한 번만)
cd app
MOACON_DEV_SERVER=http://192.168.0.12:5173 npx cap sync android
cd android && ./gradlew installDebug
```

이제 `client/src/**` 를 고치고 저장하면 **폰 화면이 바로 갱신된다.** 앱을 다시 깔지 않는다.

주의할 것:

- **이 빌드는 절대 나눠주면 안 된다.** 와이파이를 벗어나면 흰 화면만 뜬다.
  나눠줄 것은 `MOACON_DEV_SERVER` 없이 만든 것이어야 한다(워크플로가 그렇게 만든다).
- **Edge Function이 막힐 수 있다.** `supabase/functions/_shared/guard.ts` 가 허용 출처를
  확인하는데, `http://192.168.0.12:5173` 은 거기 없다. 자동 인식·가격 검색·매장 찾기를
  시험하려면 Supabase의 `ALLOWED_ORIGINS` 에 이 주소를 임시로 넣어야 한다.
  **끝나면 반드시 뺀다.**
- 소셜 로그인은 리다이렉트 주소가 달라져서 그대로는 안 될 수 있다. 로그인 상태는
  이미 저장돼 있으므로 대개 문제되지 않는다.

### 자바를 고쳤을 때 — Actions를 기다리지 않는다

USB로 연결한 뒤:

```bash
cd app/android
./gradlew installDebug
```

Android Studio(또는 command line tools)가 맥에 있어야 한다. 태그를 밀고 Actions를 기다려
APK를 내려받는 10분이 **1~2분**이 된다. 나눠줄 것만 워크플로로 만들면 된다.

### 자바를 고쳤으면 밀기 전에 컴파일부터 — Android Studio는 필요 없다

자바나 gradle을 건드리면 Actions에 올려봐야 알 수 있는 오류가 있다. 태그를 밀고 1분 반을
기다렸다가 "형이 안 맞는다" 한 줄을 보는 왕복은 낭비다. 맥에서 30초면 같은 걸 잡는다.

**Android Studio는 안 깔아도 된다.** 필요한 건 JDK와 안드로이드 SDK뿐이고, 그건 명령줄
도구만으로 충분하다. IntelliJ든 VS Code든 쓰던 편집기를 그대로 쓰면 된다.

```bash
# 한 번만 — 설치 (Homebrew 기준)
brew install --cask temurin@21              # 워크플로와 같은 JDK 21
brew install --cask android-commandlinetools

# ~/.zshrc 에 추가하고 터미널을 새로 연다
export ANDROID_HOME="$(brew --prefix)/share/android-commandlinetools"
export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"

# 컴파일에 필요한 플랫폼 (변수는 app/android/variables.gradle 에 있다)
sdkmanager --licenses
sdkmanager "platforms;android-36" "build-tools;36.0.0"
```

이제 자바를 고칠 때마다:

```bash
cd app
npm install                 # 한 번만. capacitor-android 모듈이 여기 있다
npx cap update android      # 한 번만 (플러그인을 더하거나 뺐으면 다시)
cd android
./gradlew compileReleaseJavaWithJavac
```

`npx cap update android`를 건너뛰면 이렇게 멈춘다:

```
Could not read script '.../capacitor-cordova-android-plugins/cordova.variables.gradle'
```

`capacitor-cordova-android-plugins/`와 `app/capacitor.build.gradle`은 **Capacitor가 만들어내는
파일**이라 저장소에 없다(`app/android/.gitignore`). 워크플로도 gradle 전에 `npx cap sync`를
돌리는 이유가 이것이다.

여기서 `sync`가 아니라 `update`를 쓰는 이유: `sync`는 웹 화면까지 복사해서 `client/dist`가
있어야 하는데, 자바만 확인할 거라면 그게 필요 없다. `update`는 네이티브 쪽만 손본다.

**워크플로가 실패하는 바로 그 작업이다.** 여기서 통과하면 Actions에서도 통과한다.
화면(JSX·CSS)은 컴파일이 없으니 이 단계가 필요 없다 — 그건 6-2의 라이브 리로드로 본다.

처음 한 번은 gradle과 빌드 도구를 받느라 몇 분 걸리고, 그다음부터는 30초 안쪽이다.
설치 파일까지 만들어 폰에 넣으려면 `./gradlew installDebug`를 쓴다(USB 연결 상태).

### 무슨 일이 나는지 눈으로 본다

`chrome://inspect` 를 붙이면 콘솔·네트워크가 그대로 보인다(7장 아래). **한 번 설치할 때
얻는 정보의 양이 달라진다.** 갤러리 스캔이 아무것도 못 찾았을 때, 사진을 못 읽은 것인지
바코드가 안 잡힌 것인지를 짐작하지 않고 바로 알 수 있다.

### 갤러리 스캔만은 실기기가 정확하다

폴더 이름(`Download`, `KakaoTalk`, `Screenshots`)이 제조사·기기 언어·앱 버전마다 달라서,
에뮬레이터에서 통과해도 갤럭시에서 안 걸릴 수 있다. 이건 **실기기에서 한 번은 봐야 한다.**

에뮬레이터로 대강 볼 거라면, 파일을 `adb push` 로 넣는 것보다 **에뮬레이터 안에서 직접
스크린샷을 찍는 편**이 확실하다. `adb push` 로 넣은 파일은 MediaStore에 등록되지 않아
목록에 안 잡히는 반면, 스크린샷은 정상 경로로 들어가기 때문이다.

## 7. 문제가 생기면

| 증상 | 원인과 조치 |
| --- | --- |
| 워크플로가 "ANDROID_KEYSTORE_BASE64 시크릿이 없습니다"로 실패 | 3-2를 안 했거나 이름 오타. 시크릿 이름은 대소문자까지 정확해야 한다 |
| gradle 단계에서 서명 실패 | 비밀번호나 alias가 시크릿과 다르다. `keytool -list -v -keystore moacon.keystore`로 alias를 확인한다 |
| 설치 중 "패키지가 잘못된 것 같습니다" | 서명 없는 APK다. 워크플로를 거치지 않고 로컬에서 빌드한 것을 나눠줬을 때 난다 |
| "앱이 설치되지 않았습니다"만 뜨고 이유가 없음 | 대개 **다른 키로 서명한 같은 패키지명**이다. 폰에서 기존 앱을 지우고 다시 설치한다 |
| 설치 자체가 막힘 (허용 토글이 잠김) | 갤럭시 **보안 위험 자동 차단**. 5장 참고 |
| 앱을 열면 흰 화면 | 화면 파일 경로가 어긋났다. 앱은 `https://localhost/` 루트에서 여는데 웹 기본값은 `/our-home-gift/`다. 앱 빌드는 `VITE_BASE_PATH=/`로 해야 한다 |
| 화면은 나오는데 스크롤이 안 됨 | 스크롤 상자가 둘이면 웹뷰가 어느 쪽을 굴릴지 못 정한다. `html`과 `body` 양쪽에 `overflow` 를 걸지 않는다. `overscroll-behavior: none` 도 웹뷰에서 스크롤을 먹을 수 있어 `contain` 을 쓴다 |
| 앱에서 화면이 예전 그대로 | 화면은 앱 안에 담겨 있다. 새 APK를 받아야 바뀐다 |

---

### 앱 안에서 무슨 일이 나는지 직접 보기

브라우저에서는 멀쩡한데 앱에서만 이상할 때가 있다. 웹뷰는 브라우저와 미묘하게 다르게
돌기 때문이다. 그럴 때는 **크롬 개발자도구로 앱 화면을 그대로 열 수 있다.**

1. 폰: `설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호` 를 7번 연타 (개발자 옵션 켜기)
2. 폰: `설정 → 개발자 옵션 → USB 디버깅` 켜기
3. USB로 연결하고 폰에 뜨는 허용 창을 승인
4. 컴퓨터 크롬에서 `chrome://inspect` 접속 → 목록의 모아콘 옆 **inspect**

평소 웹 개발하듯 Elements·Console·Network를 그대로 쓸 수 있다. 원인을 짐작으로
좁히는 것보다 이쪽이 훨씬 빠르다.

## 8. 웹 용어로 바꿔보면

| 앱 | 웹으로 치면 |
| --- | --- |
| APK | 배포 번들 (다만 사용자가 직접 내려받아 **설치**한다) |
| 서명 키(keystore) | HTTPS 인증서. 단, CA 없이 **자체 서명**이고 갱신이 아니라 **영구 보관**이다 |
| `applicationId` | 도메인. 한 번 정하면 못 바꾼다 |
| `versionCode` | 캐시 버스팅 해시 같은 것. 단조 증가해야 한다 |
| `versionName` | `package.json`의 `version` |
| 사이드로딩 | 스토어를 안 거치고 직접 배포하는 것 |
| Play Protect | 브라우저의 "안전하지 않은 다운로드" 경고 |
| `cap sync` | 빌드 결과(`client/dist`)를 앱 안으로 복사하는 단계. 웹의 배포에 해당한다 |

## 9. 사람이 20명을 넘어가면

지금 방식(APK 직접 배포)은 **인원이 적을 때 가장 빠르다.** 다만 늘어나면 두 가지가 걸린다.

1. **설치 안내 부담.** 위 5장의 경고 3~4개를 사람마다 넘겨야 한다.
2. **2027년부터 개발자 인증이 필요해진다.**
   [Android developer verification](https://developer.android.com/developer-verification) —
   사이드로딩에도 적용된다. 무료 계정은 **20대까지**, 그 이상은 25달러짜리 계정이 필요하다.

사람이 많아질 것 같으면 **Play Console 내부 테스트**(25달러 1회)가 낫다. 링크로 참여하면
플레이스토어에서 **경고 없이 정상 설치**되고 **자동 업데이트**까지 된다. 스토어 검색에는
뜨지 않고, 최대 100명까지 초대할 수 있다.

지금 만든 워크플로는 그때도 거의 그대로 쓴다 — 다만 Play는 APK가 아니라 **AAB**를 받는다.

**공개 배포(스토어 정식 출시)로 갈 거라면 요구사항이 더 붙는다.**
[docs/store-release.md](store-release.md)에 따로 정리해뒀다.
