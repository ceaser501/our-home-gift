## 0. 상품명을 한 글자씩 다르게 읽는다

"떠먹는 스트로베리"가 **"더먹는"**으로 나온다. 태수님이 마지막에 잡기로 한 항목이다.

### 지금까지 한 것

압축이 원인인 줄 알았다. 모델이 보던 사진이 보관용으로 눌러둔 사본(1400px, 품질 0.82)
이었고, 한글은 획 하나로 갈리니(떠/따, 반/밤) 압축 자국이 그 위에 앉으면 다른 글자가
된다고 봤다. 실제로 같은 사진이 부를 때마다 "따먹는"과 "뚜렛는"으로 갈렸다.

모델용 사본을 따로 떴다 — 1568px, 품질 0.95 (`client/src/utils/imageAnalyze.js`).
이미지 토큰은 픽셀 수로만 매겨져서 화질을 올려도 요금은 그대로다.

**절반은 맞았다.** "황금올리브 반반"이 제대로 나오게 됐고, 못 읽는 건이 없어졌고,
무엇보다 **여러 번 읽혀도 매번 같은 답**이 나온다. 흔들리던 것이 멎었다.

### 남은 것은 다른 문제다

답이 일정해졌다는 건 이제 노이즈가 아니라는 뜻이다. 모델이 이 해상도에서 그 글자를
진짜로 "더"로 본다. 화질을 더 올려도 같은 답이 나올 것이다.

여기서 쓸 수 있는 수는 두 가지뿐이다.

- [ ] **상품명 자리만 잘라서 크게 보내기.** 지금은 세로로 긴 캡처를 통째로 보내는데,
      화소 상한(115만) 때문에 폭이 700픽셀 언저리로 묶인다. 글자가 있는 부분만 잘라
      보내면 같은 화소로 몇 배 크게 볼 수 있다. 자를 위치를 알아야 하는데, 모델이 이미
      `thumbnail`로 상품 그림 위치를 짚고 있으니 같은 방식으로 상품명 위치도 짚게 하고
      두 번 부르는 식이 된다. 호출이 두 배가 된다.
- [ ] **모델을 올리기.** `claude-haiku-4-5` → `claude-sonnet-5`. 한글 판독은 확실히
      나아지지만 값이 3배다($1/$5 → $3/$15). 한 건 6원이 18원이 된다.

먼저 재볼 것: **같은 사진을 Sonnet에게 한 번 보내보고** 실제로 "떠먹는"이 나오는지.
안 나오면 모델을 올려도 소용없으니 자르는 쪽으로 간다. 두 번 부르는 값(12원)과 모델을
올리는 값(18원)을 비교하는 건 그다음이다.

관련: [scan-cost.md](scan-cost.md)

## 1. 지도와 외부 연동이 앱에서 안 된다

매장을 눌러 들어가면 지도가 뜨지 않는다. 웹(GitHub Pages)에서는 되던 것이라,
앱으로 감싸면서 생긴 문제다.

### 원인 — 화면을 여는 주소가 다르다

앱은 화면을 **`https://localhost`** 에서 연다. Capacitor의 기본값이고
(`hostname = "localhost"`, `androidScheme = https`), `app/capacitor.config.ts`에
따로 지정한 것이 없어 그대로다.

카카오 JavaScript 키는 **개발자센터에 등록한 사이트 도메인에서만** 동작한다.
등록돼 있는 것은 `https://ceaser501.github.io`일 테고 `https://localhost`는 없다.
그래서 SDK 스크립트가 401로 떨어지고, `loadKakaoMap()`이 null을 돌려주고
(`client/src/utils/kakaoMap.js:26`), 화면은 지도 없이 정보만 보여준다.

### 할 일

- [ ] **카카오 개발자센터 → 내 애플리케이션 → 플랫폼 → Web → 사이트 도메인에
      `https://localhost` 추가.** 코드 수정 없이 이것만으로 될 가능성이 크다.
      **이것만 태수님 손이고, 나머지는 아래에서 이미 했다.**
- [x] 실패 이유를 화면에 남긴다 — `client/src/utils/kakaoMap.js`가 이유를 같이
      돌려주고, `client/src/components/StoreDetailSheet.jsx`가 그대로 보여준다.
      등록해야 할 주소(`window.location.origin`)를 문장에 넣었다. 여전히 안 뜨더라도
      이제 화면이 무엇을 해야 하는지 말한다.
- [x] **T맵 길안내** — 원인을 찾았다. `intent://` 형태를 풀어주는 것은 크롬이지
      웹뷰가 아니다. Capacitor는 자기 도메인 밖의 주소를 만나면
      `new Intent(ACTION_VIEW, url)`로 그대로 넘기는데(`Bridge.launchIntent`),
      그 url의 scheme이 `intent`라서 받아줄 앱이 없다. 던져진
      `ActivityNotFoundException`은 아무도 잡지 않아(소스에 `// TODO` 로 남아 있다)
      눌러도 아무 일도 일어나지 않았다.

      앱 안에서는 `tmap://` 를 그대로 넘기게 바꿨다. 대체 주소를 실을 수 없으니
      아이폰에서 쓰던 "1.5초 뒤에도 화면이 그대로면 스토어로"를 같이 쓴다.
      `@capacitor/app-launcher`를 새로 넣지 않아도 되는 길이다.
- [ ] **주변 매장 검색**(`supabase/functions/search-places`)은 서버가 부르는
      REST라 도메인 제한과 무관하다. 지도가 살아난 뒤에 따로 확인한다.
- [ ] 확인 순서: 카카오 도메인 추가 → 지도 뜨는지 → T맵 → 매장 검색

## 2. 여러 장을 한 번에 등록하기

지금 `+`는 한 건씩만 받는다. 여러 장을 받아 바코드 번호가 같은 것끼리 묶고,
읽어낸 값을 확인시킨 뒤 한꺼번에 넣는다.

시안 네 가지를 그려뒀다 — <https://claude.ai/code/artifact/696cb219-748e-4d78-b610-58383057bbcb>

| | 전부 잘 읽힌 날 | 한 건 흐릴 때 | 기존 화면과 |
| --- | --- | --- | --- |
| A 묶음 띠 + 편집판 | 5번 눌러야 | 그 건만 고치면 끝 | 새 화면 |
| **B 카드 목록** | **1번** | 그 카드만 펼침 | **같음** |
| C 한 장씩 넘기기 | 5번 넘김 | 넘기다 만남 | 새 화면 |
| **D 빠진 것만 묻기** | **1번** | 그 칸만 물음 | **같음** |

**추천은 B를 뼈대로, 카드를 펼치면 A의 편집판, 등록 직전에 D의 질문이다.**
셋은 배타적이지 않다.

### 왜 B인가

- 전부 잘 읽힌 날에 손이 **한 번만** 간다. 카카오톡 원본은 거의 다 제대로 읽히니
  그게 대부분의 날이고, 그 경우를 빠르게 만드는 것이 여러 장을 한 번에 올리는 이유다.
- **아이폰에서는 이 화면이 유일한 다건 경로다.** 사진첩을 훑을 수 없기 때문이다
  (`client/src/utils/gallery.js`의 `isGalleryScanSupported` 참고). B로 가면
  안드로이드의 자동 찾기 결과와 아이폰의 직접 올리기가 똑같이 생긴 화면으로 모인다.
  배울 것도 만들 것도 하나가 된다.

### 이미 있는 것

묶는 규칙은 새로 만들 것이 없다. `client/src/utils/gallery.js`에 그대로 있다.

- 같은 바코드 번호면 한 건 (`seenCodes`)
- 원본(카카오톡·다운로드)이 있으면 캡처는 빼고 (`isOriginal`)
- 바코드가 사진 폭의 25%에 못 미치면 후보에서 제외 (`MIN_BARCODE_COVERAGE`)

### 할 일

- [ ] 시안 확정 (태수님)
- [ ] `+`에서 사진 여러 장 받기
- [ ] 받은 사진을 위 규칙으로 묶기 — 갤러리 훑기의 `collect()`에서 폴더를 읽는
      부분만 떼어내면 그대로 쓸 수 있다
- [ ] 묶은 결과를 확인시키는 화면 (확정한 시안대로)
- [ ] 일괄 등록 — `registerAll`과 미리 올려두기(`uploadGifticonImages`)를 그대로 쓴다
